# Research knowledge

## Research reuse policy

For a new substantive task family, inspect existing capability research before
starting an external search. Reuse completed research until the user requests an
update. If research is missing, study practical skills, methodology and reasoning,
then retain sources, applicable examples and evaluated limits. Source changes are
review signals. Current facts can still need a focused check for the task.

Save the user's stated preferences with their source and scope. During upgrades,
ask the user to confirm saved preferences before changing the capability. The
research registry reports missing, reusable and changed-source records and flags
updates with saved preferences. Its output is advisory task data.

## Knowledge relationships

The shared `vault/` stores newly learned documents independently of replaceable
package content. A research record with `source_root: vault` resolves its source
paths there. Both the shipped knowledge and durable vault are selected local KB
roots. Package replacement preserves learned files and research history.

The shared task board links current work to research records and evidence.
Capability records link distilled guidance to source hashes and related task
families. Original sources, methods and their evaluations remain inspectable.
These explicit relationships support retrieval through the current local KB and
registry. Their existence establishes recorded structure and provenance.

## Research-paper practice

The research-paper skill covers question framing, literature, method design,
evaluation, writing and review. Load its relevant reference for the current phase.
Keep a question, strongest alternative explanation, claim-to-evidence map and
clear limitations. Use a research specification to expose consequential decisions
before expensive work. Select the amount of procedure that the project needs.

## Capability commands

`harness research check research-paper` returns the saved record and preferences.
Add `--update` when the user requests a refresh. `RESEARCH_REQUIRED` means this
registry has no saved match. Its `INSPECT_EXISTING_KNOWLEDGE` action calls for
checking broader task families, skills and vault sections before new research.
For example, `research-paper` includes peer-review practice. A missing exact ID
leaves coverage unassessed. Reuse sufficient source-bound guidance and register
missing provenance, then research any remaining gap.
`SOURCE_REVIEW_REQUIRED` means a source changed or
became unavailable. `CONFIRM_SAVED_PREFERENCES` calls for the user's answer before
an upgrade. A recorded capability can remain unmeasured for model performance.
