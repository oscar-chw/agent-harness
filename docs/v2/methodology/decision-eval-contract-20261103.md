## What each observation can establish

A valid case/result schema establishes identity and byte bindings. A real bounded
execution establishes the property observed for its exact submitted subject and
fixtures. Independent semantic review can assess the visible decision against
facts, uncertainty, consequences and alternatives. Primary-source support,
actual native use and comparative benefit each need their own evidence; none
follows automatically from the other levels.

For a decision-only task, do not require an unrequested system implementation.
A proposed runtime test remains proposed until executed. For an implementation
claim, execute the actual response-bound artifact under the frozen check. If a
response supplies a finite policy/action model, a simulator can check that
model's traces; it cannot prove a proposed real service implements it. Never
substitute the evaluator's reference implementation based only on a choice enum.

Each family in JSON specifies a **bad but fluent** control by its consequence,
not a sample learner response. Correct vocabulary must not rescue duplicate

not executed calibration results or responding-agent answer keys.

Include a recommendation-invariant change: irrelevant names, presentation or
row order cannot force a reversal. A binding changed constraint can change the
permissible set, while an irrelevant change should preserve it. Always repeating
and always flipping must both be refutable. Root must check the appropriate
invariant rather than reward the existence of a changed answer.

## A typed key cannot certify reasoning

An expected enum can detect malformed labels and test a declaration when that is
the actual task. It cannot distinguish a supported decision from guessing,
memorization or a fluent contradictory explanation. A response can name the right
strategy while its submitted query or policy breaks the invariant; another can
use a different allowed label and preserve every consequence.

For any reasoning claim, independently review concise observable rationale tied
to supplied facts, material unknowns, counterevidence and changed constraints,
alongside the relevant outcome/source checks. Do not request hidden chain of
thought. Claim only scoped observable decision adequacy, never private reasoning,
general expertise or measured transfer from a typed answer key alone.

No credit accrues from framework words, headings, citations counted without
support, a fixed number of alternatives, prose length or tool-call counts.
Calibration must accept sound and alternative controls and reject each named bad
control for its intended failure. A closed gate, wrong hash or collateral missing
field cannot stand in for detecting the actual domain defect. Disagreement stays
visible and unresolved when its evidence/requirement remains unsettled.

## Freeze, bind and preserve absence

Before learner runs, root pins supplied facts, hard constraints, allowed evidence,
case mode, permissible alternatives, unacceptable consequences, required claim
axes, oracles, extraction/interpretation rules, environments, calibration and stop
rules. Source bindings distinguish actual primary captures, authored notes and
read receipts. This worker read local retained notes; it did not acquire or verify
their upstream primary sources. Missing local source bytes remain missing.

Bind task/variant, exact prompt/context and retrieved spans, invocation, response,
submitted artifacts, checker/trace/reviewer and all relevant versions/hashes.
Byte identity does not authenticate provenance or entailment. Keep reference
solutions/reviewer keys out of the learner context; exposure and tuning make a
case development material. Never discard the exposed failure or call it held-out.

Use PASS, FAIL, NOT_RUN, INCONCLUSIVE and INVALID for the exact named check.
Missing required execution does not become PASS; a proposal does not become an
execution. Do not require optional/unrequested implementation to pass a decision
review. Root decides the claim verdict only from its **previously frozen** required
axes. Source support, native use, implementation and efficacy remain separate.
Hard authority, integrity, source-scope and domain invariant failures cannot be
traded against fluent prose, other cases or fewer tokens.

## Whole-usage record, separate from node2 consequence checks

The JSON exposes null baseline/candidate totals, explicit measurement NOT_RUN,
an empty invocation ledger and required fields; empty/unknown is never zero or
a successful comparison. Record every actor/coordinator/retriever/reviewer/grader/
maintenance call, including failed attempts, retries and adaptation. Preserve raw
provider events and accounting semantics. Input/output totals include injected
instructions and consumed tool output; cache and exposed reasoning subsets are
reported separately and counted once according to provider semantics.

For a later authorized node6 comparison, charge baseline B for all baseline
work and candidate C for all candidate work plus registered creation/adaptation/
failed revisions. Freeze common-charge allocation and maintenance amortization;
charge each call once and never inflate B to pay for candidate research. Missing,
partial, ambiguous or resumed usage is unavailable until actually resolved, not
an estimate of zero. Machine-only work can be zero model tokens only when that
boundary is evidenced; no such result is invented here.

Quality must not regress on required cases/dimensions and complete C must not
exceed B. Billing savings, a cheaper model, smaller packets, a short final answer
or one successful run do not satisfy that rule. An improvement claim additionally
needs a measured benefit and adequate evidence. Public-case success alone cannot
establish held-out efficacy or universal superiority.
