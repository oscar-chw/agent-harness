# Decisions with partial knowledge

3 November 2026. Four hypothetical candidate-guidance cases for node4.
They do not establish current search completeness, a new guard rule or native
behavior. Missing evidence limits a claim; it need not stop independent work.

## 1. Trustworthy complete miss

Suppose the declared authorised scope and query are known, its current sources
were accessible, and search completed without hidden omissions or truncation.
No supporting hit was found. Proceed with “not found in this search/scope,”
not “the fact does not exist.” A lexical miss still does not prove semantic
absence. Use a focused allowed query/source check if it can change the answer;
continue work that does not depend on the missing fact. If asked for the exact
fifteen historical failed-fetch identities, an aggregate count is not a list.
The identities remain unknown. Reporting that gap needs no approval;
broader access needs its own authority.

## 2. Partial search, usable hit

A permitted r5 passage supports item15's corrected read extent, but another
potentially relevant source is unreadable or omitted by a limit. Preserve the
usable hit: answer what that revision supports, cite it and disclose partial
coverage. Do not convert one hit into complete recall, consensus or a claim
that no later correction exists. Hold only conclusions/actions that depend on
the missing material; unrelated valid results can proceed. Acquire the smallest
permitted missing span when consequential. Approval matters if doing so crosses
an ungranted scope/effect boundary, not because every partial result requires
human reassurance.

## 3. Explicit permission refusal

A needed source is explicitly denied or revoked, rather than merely absent.
Keep the affected answer unresolved and preserve the rejecting layer safely.
Do not read another cached copy of the denied body, switch tools/accounts or
infer permission from index visibility. Continue independent authorised work.
If the original layer supports approval, request the exact necessary effect
once and reuse a valid applicable grant. Chat consent is not a native grant
without a consumer. If no approval path exists, name the needed owner action.
An I/O error alone must not be reclassified as revocation or approval.

## 4. Unrelated inaccessible source

An allowed current source settles a bounded task; a separate source, known from
permitted metadata to be irrelevant, is inaccessible. Complete the supported
task without opening that source, seeking needless approval or rereading the
whole corpus. Do not claim corpus-wide completeness. Its contents/access remain
unknown, and the task result cannot grant access later. Reassess under case2
if its relevance changes.
