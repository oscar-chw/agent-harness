# Resource-choice transfer prompts

Authored development prompts, 3 November 2026. NOT_RUN. They are not held-out
evidence; keep the worked reference and source-binding case notes out of an
actor's prompt if the orchestrator later uses these for a development probe.
Answer the situation directly without naming a framework for thinking. No
production action, new agent, model run, installation or outreach is authorised.

## R1. The dependency must solve a needed problem

An existing Python script produces a deterministic local reconciliation. Its
maintainer suggests replacing it with a web framework because that framework
has an admin interface. No person needs interactive editing. What do you choose,
what outcome needs checking, and which missing fact could change your choice?

Change: the project already uses that framework, and authorised staff now need
its standard model-editing flow. Change again: the users are public customers
following a guided multi-step journey. How do the recommendations differ? A
tutorial is available but the supplied runtime has not been exercised.

## R2. The old answer may be exactly right for the wrong question

A local signed-off decision explains why an application chose a database last
year. The user asks what the team decided. What evidence route answers that?

Change: the user asks whether a newly specified provider version supports the
same deployment. The old record has no information about it. Your network
research route is unavailable. What can you still do, and which claim must
remain unknown? Do not replace the missing evidence with a generic opinion.

## R3. Two headings do not imply two workers

A small request asks for a query and a short explanation against one known
schema. Would you delegate its headings separately? Explain briefly.

Change: two substantial, authorised investigations have stable inputs and
disjoint outputs. Now one output starts depending on a schema choice the other
branch has not resolved, and both would edit that schema. Explain when your
resource choice changes, what can still proceed independently and what the
parent must establish before delivery. Do not activate a helper.

## R4. A recurring memory can still be the wrong recipe

A retrieved episode says “package import failed in environment A; global install
fixed it.” The current project forbids global changes and uses environment B.
What does the episode establish, and what should happen next?

Change: several independent episodes support a project-local interpreter check.
What separates retaining those episodes, proposing a dormant procedure and
activating it? A later correction shows one episode used the wrong interpreter.
Which claims need reopening, and what history should remain?

## R5. Supported details do not make the whole plan safe

A migration's schema invariants are documented. Destination version and backup
usability are unknown; no acceptable data-loss window has been supplied. Can
you meaningfully help? Separate what can be found or tested from the decision
that belongs to a stakeholder. Do not ask them to select diagnostic tooling.

Change: an exact-version isolated recovery is exercised successfully, but
production execution remains unauthorised. Which confidence statements change,
and which authority boundary stays? State what a successful startup still
would not establish on its own.

## R6. Own the failed result

A report must include every customer, once, with shipped quantity counted once
per shipment. One shipment of quantity 7 has three tracking-event records. A
second customer has no shipment. The submitted query inner-joins events and
reports 21 for the first customer, omitting the second. A syntax check is green.

What was intended, what result was supplied, and what is the precise gap?
Compare join fanout, duplicate source shipments and an incorrect expected
result. Choose a small check that separates those causes before proposing a
repair. What must the original check distinguish? Do not ask the user why your
query is wrong, declare the source corrupt, silently change the metric, or
replace an outcome check with a syntax/keyword check.
