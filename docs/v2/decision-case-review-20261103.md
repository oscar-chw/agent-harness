## Checks and limits

New sql_outcome evaluates the supplied query, not a known-good replacement. It
creates fresh in-memory fixtures; only fixture SELECT/read and listed functions
are allowed. File attach, schema reads, writes and extension loading are refused.
VM-work, query, fixture, row and result limits apply. This is a bounded local
grader, not a general SQL sandbox, independent authenticated oracle or OS guard.
SQLite's count(*) authorization callback can have an empty column/no database;
the narrow fixture-table exception was measured locally and reconciled with the
[official authorizer reference](https://www.sqlite.org/c3ref/set_authorizer.html).

Initial new case-validation tests exposed 2 defects: an empty consequence object
passed, and Python True equalled 1. Both failures were preserved. The evaluator now
requires nonempty outcomes and type-distinct JSON values. Seven in-memory bad
case controls reject fanout, stale metric, false confirmation, systemic retries,
forbidden evidence, missing-evidence guesses and ignored accessibility. These
controls test the instrument; they do not manufacture responding-agent evidence.

No new default prompt, native configuration, installed policy, skill or release
is promoted by this work. Source/fixture checks and native quality stay separate.
